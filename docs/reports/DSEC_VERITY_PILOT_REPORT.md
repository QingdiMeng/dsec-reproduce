# 本地工具盘按需完整性与 Docker/DSec 配对验收

2026-10-06，r5 安装候选实机验收通过。启动解析不再全文读取 22 GiB
verifier 工具盘，完整性约束仍生效；完整 episode 的 Docker/DSec 时长
差距仍存在。未公开发布或替换已有服务。

## 验收对象和方法

核心安装包为 `0.1.0.dev0`，wheel SHA-256 为
`11b2df99f8e305c332da1dd8d2b7adce6a3a25a1d2866adea6875c296e7eef5b`。
独立源码重建、新 venv 的 49 项核心测试和 55 个运行文件摘要检查通过；
准备阶段的 27 项实验回归通过。guest fixture 和可选 TB2.1 应用包复用，
不是新 guest 构建或短 GRPO 重跑。

工具盘内容摘要仍为
`a487ff4cbdac2c2193ff4c451c0e33e3683bcce1b9ef1909a831b9e7a33da490`，
逻辑大小 23,622,320,128 B（22 GiB）。管理员封存相同字节，确认原
SHA-256 后生成受保护凭据；运行时核对凭据与内核摘要，读取数据页时
由内核校验。没有以文件名、stat 或缓存命中替代校验。

冷边界只对本实验新文件及其 loop backing file 做 fadvise，数据页非
驻留由 root 检查。这是测量条件，不是运行时的缓存回收优化。

## 完整性和一次性准备

真实检查全部通过：封存文件写入被拒绝；相同字节的未封存副本无法
通过解析；在卸载的独立小测试卷上损坏数据后，重新挂载读取返回 EIO。
损坏检查没有修改正式工具盘或旧制品。

复制、建树和全文摘要确认共 **43.556 s**，独立卷物理占用
**17,461,133,312 B（16.26 GiB）**，逻辑卷 26 GiB。此次保留旧制品的
独立验收增加了磁盘占用，不代表生产部署必须保存两个副本。未修改根
文件系统特性；成功后新卷只读挂载，无 fstab 或服务安装。

非 root 新进程在冷输入下解析耗时 **0.516 ms**，进程 `read_bytes=0`，
工具盘数据驻留页仍为 **0**。这个时间是完整性解析，不是 VM 启动时间。

## 完整后端成本

同固定轨迹、同离线初始化、同只读工具盘；两端各运行两个任务三次，
DSec 另运行三次准备态分叉。15 次评分全部为 1。完整 cgroup 子树包含
辅助服务，250 ms 采样无错误，物理 NVMe 写入校准通过。

下表比较前后 DSec 相同阶段。r4 使用全文摘要，r5 使用新受保护卷，
也包含存储布局变化，不能当成严格的单变量微基准。

| DSec 后端准备 | r4 | r5 |

| 墙钟 | 15.155 s | 0.928 s |

整个 DSec 批次的内核内存峰值从 24.402 GiB 降到 2.749 GiB。该批次比
Docker 多基线准备与三个分叉，不能把批次峰值当作同任务配对。等数量

准备态分叉阶段 DSec **2.737 GiB**，保留基线的成本未扣除。这次没有

episode 墙钟与 r4 接近。
